# 选片页面时间排序与跨组导航设计

## 背景

当前选片页面存在以下问题：
1. 照片按时间降序排列（最新在前），不符合用户从早到晚的浏览习惯
2. 有分组和无分组的照片分开处理，无分组照片按日期分组而非按时间间隔聚合
3. 大图预览只能在同组或同日期内导航，无法跨组切换

## 需求

1. **时间排序**：照片和照片分组按时间从早到晚（升序）排列
2. **无分组照片聚合**：附近时间段内的无分组照片聚合在一起展示
3. **跨组导航**：大图预览时左右键可跨分组切换所有照片

## 设计方案

### 1. 排序逻辑修改

**后端修改** (`src/web/app.py`)：

- 查询排序：`order_by(Photo.captured_date.desc(), Photo.id.desc())` → `order_by(Photo.captured_date.asc(), Photo.id.asc())`
- 分组排序：按组内最早照片时间升序排列

### 2. 无分组照片时间聚合

**当前逻辑**：
```python
# 有分组照片按 group_id 分组
grouped: dict[int, list[Photo]] = {}
# 无分组照片按 captured_date 分组
ungrouped: dict[str, list[Photo]] = {}
```

**修改为**：
```python
# 统一处理，所有照片都有组
all_groups = []  # 每个元素：{type, photos, sort_key}
```

**聚合规则**：
- 无分组照片按 `captured_at` 排序
- 时间间隔小于阈值（2分钟）的照片聚合为一个"虚拟组"
- 虚拟组使用组内最早 `captured_at` 作为排序键
- 虚拟组视觉样式与连拍组一致，标记为"照片"而非"连拍"
- 虚拟组不显示"选最佳"按钮（因为不是连拍）

### 3. 大图预览跨组导航

**当前问题**：`_get_review_neighbors` 只在同组或同日期内查找前后照片

**修改方案**：
- 返回该照片在整个序列中的前后照片 ID
- 左右键在完整序列中切换，到达组尾自动跳到下一组首张

**API 变化**：
- 现有 `/api/photo/{id}/review` 返回 `prev_photo_id` 和 `next_photo_id`
- 改为：返回该照片在整个序列中的前后照片 ID

### 4. 前端页面变化

**选片页面** (`select.html`)：
1. 分组显示顺序：从早到晚排列
2. 分组标题：显示该分组的最早拍摄时间
3. 保持现有 UI 交互不变

**大图预览** (`reviewModal`)：
1. 左右箭头按钮：跨组导航
2. 快捷键：←/→ 跨组切换
3. 导航按钮状态：到达序列首/尾时禁用

## 影响范围

- 选片页面显示顺序从早到晚
- 大图预览可跨组导航
- 现有功能（选中/淘汰/标签等）保持不变

## 测试要点

1. 验证选片页面照片顺序为从早到晚
2. 验证无分组照片按时间间隔正确聚合
3. 验证大图预览左右键可跨组导航
4. 验证到达序列首/尾时导航按钮正确禁用
5. 验证现有功能（选中/淘汰/标签等）正常工作
