# eBird 观鸟记录同步设计

## 背景与目标

飞羽志当前根据 `Outing` 和 `Photo` 聚合本地观鸟记录，但不能把中国观鸟记录中心的报告整理成 eBird 可导入的数据。目标是在现有“观鸟记录”模块内增加一条可恢复、可审查的离线同步流程，并同时把记录页面由卡片列表改造成目录式浏览界面。

同步以中国观鸟记录中心报告为主数据源，本地照片识别记录只用于补充证据、学名、GPS、时间和远端报告缺失的鸟种。最终产物是 eBird Record Format CSV。应用下载 CSV 后打开 eBird 官方导入页，由用户选择文件并在 eBird 完成上传；应用不调用不存在的 eBird 个人清单写入 API，也不自动操作 eBird 网页。

成功标准：

- 用户可以维护观鸟记录中心 Token，并能识别 Token 失效。
- 用户可以为当前外拍快捷拉取候选报告，也可以按日期范围批量拉取。
- 系统不会自动绑定含糊的本地外拍与远端报告。
- 用户可以审查物种映射、补齐 eBird 必填字段并生成有效 CSV。
- 同步草稿和导出历史可恢复，系统能够提示重复导出或潜在重复上传。
- “观鸟记录”页面使用左侧年/月目录和右侧详情，不再使用卡片列表。

## 范围与约束

第一版包括记录获取、候选匹配、人工绑定、鸟种映射、人工确认、CSV 导出、本地同步状态、Token 配置和观鸟记录页面改版。

第一版不包括：

- 保存观鸟记录中心账号或密码；
- 自动登录或自动续期 Token；
- 自动操作 eBird 网页或判断 eBird 是否上传成功；
- 照片、录音或视频上传；
- 从 eBird 回写中国观鸟记录中心；
- 通用多平台同步框架。

观鸟记录中心接口属于网站内部接口而非正式公开 API。客户端必须隔离接口细节，响应格式变化只能使拉取失败，不能破坏已有缓存、草稿或本地记录。

## 总体架构

现有观鸟记录页增加单条记录的“同步到 eBird”入口，以及按日期范围操作的“批量同步”入口。同步数据流为：

```text
观鸟中心报告 + 本地 Outing/Photo
              ↓
      候选匹配与人工绑定
              ↓
          同步草稿
              ↓
   鸟种映射与清单信息确认
              ↓
          校验与预览
              ↓
    eBird CSV + 打开导入页
```

后端按职责拆为四个组件：

1. `BirdReportClient`：从秘密配置读取 Token，请求本人报告，并把远端响应规范化。它不负责业务匹配或持久化用户确认结果。
2. `RecordMatcher`：根据日期筛选候选报告，并用地点文本、坐标等信息提供排序提示。候选结果不产生自动绑定。
3. `EBirdMappingService`：合并远端报告与本地外拍数据，完成 taxonomy 映射、时间建议和字段校验。
4. `EBirdExportService`：生成 eBird Record Format CSV，保存导出批次和内容摘要，并返回官方下载页面地址。

外部请求、映射逻辑、数据库操作和 Web 路由保持独立，以便使用固定样本测试而不访问真实网络。

## Token 配置与安全

现有设置页新增“中国观鸟记录中心”配置区，包含：

- 密码样式 Token 输入框；
- “保存并测试”“仅测试连接”“清除 Token”操作；
- 连接状态、最近验证时间，以及接口能够返回时的当前用户名；
- 获取 `X-Auth-Token` 的简短帮助说明。

Token 只保存在本机 `config/secrets.yaml`，`config/secrets.example.yaml` 只增加空字段。后端读取配置时可以使用 Token，但任何读取配置的页面或 API 都不得返回原值；页面仅显示是否已配置。日志、异常文本、诊断信息和测试快照不得包含 Token。

每次拉取前验证 Token。远端返回 `401` 或 `403` 时停止本次拉取，不做循环重试，并提示用户前往设置页更新 Token。Token 过期不影响已有报告缓存、草稿编辑或 CSV 导出。

## 数据模型

新增以下持久化实体：

### `BirdReportReport`

缓存规范化后的远端报告，至少包含：

- 远端报告 ID（唯一键）；
- 观测日期、地点名称、经纬度和报告摘要；
- 规范化鸟种列表和必要的观察信息；
- 远端内容指纹、首次及最近拉取时间；
- 为兼容接口变化而保留的受控原始响应 JSON。

同一远端 ID 重复拉取时更新缓存。若内容指纹变化，不覆盖用户在同步草稿中确认过的字段，而是把关联的活动草稿标记为“需修正”并展示差异。

### `EBirdSyncDraft`

表示一份准备导出的 eBird checklist，包含：

- 可空的本地 `outing_id`；
- 一个远端报告 ID；
- 确认后的地点名称、经纬度；
- 观察方式、开始时间、时长、距离、观察人数和完整清单标记；
- 状态、创建及更新时间；
- 生成建议值所依据的照片时间范围。

远端报告允许在没有本地外拍时单独转换。同一远端报告同一时间最多存在一个活动草稿；已经标记上传的草稿可复制为新修订草稿，但必须提示可能产生重复清单。

状态依次为：

```text
待匹配 → 待确认 → 可导出 → 已导出 → 用户标记已上传
                 ↘ 需修正 ↗
```

打开 eBird 导入页不能自动产生“已上传”状态。该状态只能由用户手动设置，并可选填 eBird checklist ID。

### `EBirdSyncItem`

表示草稿中的一条鸟种记录，包含：

- 来源：观鸟中心、本地补充或两边共有；
- 观鸟中心名称、本地名称、学名和 eBird taxonomy code；
- 数量；
- 是否纳入导出；
- 映射和人工确认状态。

观鸟中心鸟种默认纳入导出。本地独有鸟种默认不纳入，显示关联照片作为证据；用户确认加入后，默认数量为 `X`，不得使用照片数量推断个体数量。

### `EBirdExportBatch`

记录每次成功导出的文件名、生成时间、内容摘要和草稿版本。相同内容再次导出时提示已有相同文件；草稿变化后允许生成新版本。CSV 生成失败不得新增批次或推进草稿状态。

## 报告匹配与数据合并

当前外拍快捷同步按外拍日期获取候选远端报告；批量同步允许用户选择起止日期。候选按日期、地点文本相似度和坐标接近程度排序，但系统不自动绑定最高分结果。日期相同但地点不能唯一判断时，必须由用户选择。

合并遵循以下优先级：

- 观鸟中心报告决定已有鸟种及其数量；
- 本地记录补充照片证据、学名、GPS 和远端缺失鸟种；
- 任一来源出现无法唯一映射的鸟种时进入人工确认；
- 冲突不会静默覆盖，页面同时展示两侧值。

鸟种映射优先使用稳定的学名和 eBird taxonomy code，中文名仅用于展示和候选搜索。映射表必须可独立更新并记录版本，以便 taxonomy 更新后识别需复核的旧草稿。

地点映射以已确认坐标为准、名称为辅。远端报告没有坐标时使用本地外拍照片的有效 GPS；仍无坐标时必须由用户填写或确认，不能根据同名地点自动猜测坐标。

## 时间与努力量建议

eBird 必填的观察方式、开始时间、时长、距离、观察人数和完整清单标记均在确认页展示，缺失项必须人工补齐后才能导出。

照片时间建议规则：

- 开始时间取该外拍最早一张有效照片的拍摄时间；
- 时长取最晚与最早照片的时间差；
- 只有一张照片或跨度不足 10 分钟时，建议时长为 10 分钟；
- 跨日、跨度超过 12 小时或缺少有效照片时间时不自动采用，并标记异常；
- 相邻有效照片时间间隔超过 2 小时时提示“建议拆分清单”，但不自动拆分远端报告；
- 页面显示推导依据，例如照片数量及首末时间。

所有推导结果只是可编辑的建议值，不能覆盖用户已经确认的字段。

## 页面设计

### 观鸟记录主页

页面改为双栏主从布局：

- 左侧目录按“年 → 月 → 日期与地点”分组，可折叠并支持按日期、地点或鸟种搜索；
- 目录叶节点显示物种数量和同步状态；
- 右侧显示当前节点的记录摘要、鸟种记录、外拍照片和同步/导出历史；
- 切换目录节点只刷新详情区域，不重新加载整个页面；
- 顶部提供“拉取观鸟中心记录”和“批量同步到 eBird”；
- 单条详情提供继续绑定、确认、导出或标记上传等与状态相符的操作；
- 窄屏下左侧目录收进可开关的抽屉。

现有卡片式观鸟记录列表被移除。页面继续复用现有导航、Bootstrap 样式和本地资源，不引入新的前端框架。

### 四步确认流程

1. **获取与绑定**：展示本地外拍和候选远端报告，用户确认绑定；也允许无本地外拍的远端报告继续转换。
2. **鸟种映射**：并列显示观鸟中心、本地和 eBird 名称，展示照片证据；解决未映射项并选择是否加入本地补充鸟种。
3. **清单信息**：确认地点、坐标、观察方式、开始时间、时长、距离、人数和完整清单标记，并展示时间推导和拆分提示。
4. **预览与导出**：逐项校验，预览最终 checklist，生成并下载 CSV；页面随后尝试打开 eBird 官方导入页，同时保留手动打开按钮。

浏览器阻止新窗口时不影响 CSV 下载和草稿状态。

## 错误处理

- Token 缺失或失效：保留全部缓存和草稿，提示配置入口。
- 远端超时、限流或不可访问：显示可重试错误，不修改已有数据。
- 响应格式变化：保存安全的诊断信息，拒绝不完整数据进入映射流程。
- 远端内容变化：显示差异，将草稿标记为“需修正”，不覆盖人工确认值。
- 鸟种未映射或一对多：阻止导出并定位到具体鸟种。
- 地点、坐标或努力量字段缺失：阻止导出并定位到具体字段。
- CSV 写入失败：不新增导出批次，不改变草稿状态。
- eBird 页面无法打开：保留 CSV 下载及手动打开链接。

## 测试与验证

单元测试覆盖：

- 远端响应规范化和敏感信息过滤；
- 候选筛选与排序，不产生自动绑定；
- 鸟种合并、未决映射和本地补充默认值；
- 照片首末时间、10 分钟下限、12 小时异常和 2 小时间隔检测；
- 必填字段校验、CSV 转义、列顺序和日期格式。

数据库测试覆盖迁移、远端报告去重、内容变化处理、活动草稿约束、状态转换和重复导出摘要检测。

Web 测试覆盖 Token 保存/测试/清除、配置脱敏、目录数据接口、报告拉取、人工绑定、确认、校验、CSV 下载和用户标记上传。所有观鸟中心响应使用固定样本模拟，自动测试不得依赖真实账号或网络。

CSV 使用固定期望结果验证 eBird Record Format，尤其验证 `X` 数量、中文名称映射、观察方式字段和无表头/编码要求。页面完成后对桌面双栏和窄屏抽屉进行视觉检查。

## 配置与迁移

数据库初始化沿用项目现有的幂等迁移方式：创建新表和索引，不重写现有 `photos`、`outings` 或 `species` 数据。配置示例增加空的观鸟中心字段；真实 Token 只进入被忽略的本地秘密文件。

视觉伴侣产生的 `.superpowers/` 目录属于本地设计临时文件，不进入版本控制。
